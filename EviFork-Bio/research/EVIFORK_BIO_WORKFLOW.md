# EviFork-Bio — 冲突证据驱动的生物因果假设 Agent

这是 FLASH-P 的可选研究流程。目标是保留竞争机制，通过扰动区分它们。确定性入口为仓库根目录的 `python -m evifork_bio`；实现与命令见 [模块说明](../evifork_bio/README.md)。

## 文献与假设

逐条记录 source、target、sign、doi、context 和证据定位，不为达成共识而删除少数证据。区分物种、组织、时期、条件和遗传背景：不同已知 context 的相反作用不是同一机制内的矛盾。未知条件明确记为未知，不自行补全。运行器拒绝混合 context 的规范化输入；上游导入器的粗粒度 context 仍需人工复核。

DOI 格式正确不等于能解析，能解析不等于支持主张。独立证据审查提供真实标签；Agent 自信度不能当作测量可靠度。没有审查标签就报告 `unfitted_prior_only`。

## 执行顺序

1. 在拟合和网络选择前固定原始语料、规范化规则、划分种子和参数。按论文 DOI 与相同扰动签名的连通分量，联合划分训练、校准、查询、最终测试。
2. Builder 只读训练材料，禁止读其他角色的结果或其原始论文。旧完整精炼网络不能冒充当前划分下的无泄漏 FLASH-P 对照。
3. 保留同一边对的所有已观察冲突状态。重复论文只算一个来源。sign=0 是缺边主张；可选的 omission prior 是建模假设，不能写成已有文献证明。
4. 对每个假设调用原 FLASH-P 代数模拟器。未映射、非收敛、数值异常必须报告；不得写成确定的“无变化”。
5. 用训练扰动拟合图后验；校准集只拟合预测温度。按预期信息增益/成本排序候选干预；选定前禁止读取真实结果。
6. 新实验提议只输出预测和假设分歧。收到有实际 provenance 的真实观测后，调用 `observe` 写入另一个运行状态。不得编造结果来推动流程。

## 原 FLASH-P 对照

在每个划分内独立运行原 Builder/Judge/Refiner，仅提供该划分的训练材料，并保留完整调用记录。网络目录可提供 `hypothesis_training_manifest.json`，包含该次 `split_manifest.json` 中的 `training_claims_sha256` 与 `used_heldout_outcomes: false`。

程序核查声明和训练边支持关系，但无法证明隐藏的 LLM 知识或人工操作没有泄漏。已有精炼网络统一标记为 reference-only。不要把原网络重放和重新运行原完整 Agent 管线混为一谈。

## 报告

报告 accuracy、NLL、三分类 Brier、ECE、可靠性分箱、覆盖率和每个预算下的轨迹。真实数据没有机制真值时，不能将熵下降叫作机制识别正确率。仅合成已知拓扑控制报告真机制后验与达到 0.95 的成本；未达到为 null，不是零成本。

本仓库提取物可能已反映上游验证和模型选择。当前评估只能称为回顾性提取物留出，不能声称严格从未见过该文献，更不能称为前瞻性生物发现。正式研究还需要冻结原始语料、盲法提取、独立审查、更多划分及预先登记的比较方案。
